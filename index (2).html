SQL · фрагмент витрины нагрузки
-- средняя нагрузка по сотруднику за скользящие 4 недели
WITH shift_load AS (
  SELECT e.employee_id,
         s.shift_date,
         SUM(s.hours) AS daily_hours
  FROM shifts s
  JOIN employees e   ON e.employee_id = s.employee_id
  JOIN departments d ON d.department_id = e.department_id
  JOIN preferences p ON p.employee_id = e.employee_id
  WHERE s.shift_date >= CURRENT_DATE - INTERVAL '12 months'
)
SELECT employee_id,
       shift_date,
       AVG(daily_hours) OVER (
         PARTITION BY employee_id
         ORDER BY shift_date
         ROWS BETWEEN 27 PRECEDING AND CURRENT ROW
       ) AS avg_load_4w
FROM shift_load
ORDER BY employee_id, shift_date;

Task

Product cards had no shared formatting standard and weren't systematically mapped to categories — some were sent back for rework, others landed in the wrong category, hurting visibility and conversion. Moderation took up to 7 days, and up to 40% of cards were bounced back for revision.

The goal wasn't a one-off cleanup but a repeatable process: gather requirements, formalize category-assignment rules, and set up generation for new cards so the system could handle new listings on its own.

Actions
  • Root-cause analysis via "5 Whys" — why cards drifted from standards and categories
  • Requirements gathering from the marketing and product teams
  • Mandatory-field checklist and Tone of Voice, signed off by stakeholders
  • Card validation logic as a UML Activity Diagram
  • 21 categorization business rules formalized into system requirements (attribute → category mapping)
  • Specification for developers: CRM integration with an external API for card auto-generation
  • Non-functional requirements: response time under 3s, batch processing up to 500 cards per run
  • UAT with 5 pilot managers; rules adjusted based on feedback
